# 自动入库：按媒体目录自动建库 + 自动扫描

> 现状缺口（2026-10-20 实测）：115 `媒体目录` 下有 `电影/电视剧/动画`，本地镜像库
> 只有 `电影/电视剧`，而 Lux 只注册了一个库（`name=电影, kind=MOVIE`）。
> 结果 web 只显示电影，电视剧/动画永远不会出现——因为没有任何库指向它们。

## 1. 规则表

| 媒体目录分类 | 自动创建的库 | kind | 根路径 |
| --- | --- | --- | --- |
| `电影` | 电影 | MOVIE | `<mirror_root>/电影` |
| `电视剧` | 电视剧 | SERIES | `<mirror_root>/电视剧` |
| `动画` | 动画 | SERIES | `<mirror_root>/动画` |
| `晚会` | 晚会 | SERIES | `<mirror_root>/晚会` |
| `演唱会` | 演唱会 | SERIES | `<mirror_root>/演唱会` |
| 其它一级分类 | 同名 | 含「电影」→ MOVIE，否则 SERIES | 同名目录 |

用户已确认：**动画独立成库**；**晚会/演唱会也自动成库**；**建库后自动全量扫描**。

## 2. 触发点（两个，缺一不可）

1. **归档 run 结束**：本轮新出现的分类目录 → 立即建库并入扫描队列。
2. **启动对账**：把 `媒体目录` 的一级子目录与已注册库做比对，补建漏掉的
   （覆盖历史数据、以及进程在两次之间挂掉的情况）。

## 3. 幂等与安全

- 幂等键 = **库根路径**（`mirror_root/<分类>`）：已存在则不重复创建。
- 只处理 `media_root` 的**一级子目录**，不递归（避免把某部片的子目录当分类）。
- 目录为空（没有任何 strm/nfo）时**不建库**，避免产生空库。
- 建库失败只记 WARN，不打断归档 run。

## 4. 自动扫描策略

建库成功后入队一次**全量扫描**，与手动扫描走同一条任务队列（复用 `admin_start_library_path_scan`），
不另起并发通道；扫描失败重试沿用现有任务重试逻辑。

## 5. 前置修复（同一批做）

`lux-library` 里**没有 `动画` 目录**，说明流水线写镜像时没覆盖动画分类。
不修这条，动画库建出来就是空的。需要一起查：归档分类 → 镜像生成的分支。

## 6. 验收标准

1. 清空库表后跑一次归档 run：`媒体目录` 下每个非空分类都出现对应库，且扫描已入队。
2. 再跑一次：库数量不变（幂等）。
3. 新增 `动画` 分类并放入一部片 + 重跑：动画库自动出现，且能在 web「媒体库」看到。
4. 空目录不产生库。
5. 历史数据（已有目录、无库）在进程重启后自动补齐。
