# 自动入库：按媒体目录自动建库 + 自动扫描

> 状态：**已实现**（2026-10-21），代码 `src/application/archive/auto_library.rs`，
> 规范已并入 `docs/archive-pipeline.md` §5.6。
>
> 原始缺口（2026-10-20 实测）：115 `媒体目录` 下有 `电影/电视剧/动画`，本地镜像库
> 只有 `电影/电视剧`，而 Lux 只注册了一个库（`name=电影, kind=MOVIE`）。
> 结果 web 只显示电影，电视剧/动画永远不会出现——因为没有任何库指向它们。

## 1. 规则表

**一个类型一个库**，和电影、电视剧的做法完全一致。地区（国内/国外）、年代是库**里面**的目录层，
不拆库。目录结构见 `docs/archive-pipeline.md` §4：`<类型>/<地区>/<年代>/<片名 (年份)>/`。

| 媒体目录一级分类 | 自动创建的库 | kind | 根路径 |
| --- | --- | --- | --- |
| `电影` | 电影 | MOVIE | `<mirror_root>/电影` |
| `电视剧` | 电视剧 | SERIES | `<mirror_root>/电视剧` |
| `动画`（`国内`/`国外` 都在库内） | **动画** | MIXED | `<mirror_root>/动画` |
| `动漫`（动画的另一种拼法） | 合并进「动画」 | — | 追加为「动画」的第二个根 |
| `综艺` | 综艺 | SERIES | `<mirror_root>/综艺` |
| `纪录片` | 纪录片 | MIXED | `<mirror_root>/纪录片`（板块里既有纪录电影也有系列） |
| ~~`特摄剧`~~ | **已取消**（2026-10-23） | — | 特摄按形式归类：剧集 → `电视剧`，电影 → `电影`；残留目录不再建库 |
| `REMUX` | 影视原盘 | MIXED | `<mirror_root>/REMUX`（内含 `<类型>/<地区>/<年代>/<片名>`，2026-10-23 起 remux 单独成库；目录名保持 ASCII，库显示名是中文） |
| `晚会` | 晚会 | MIXED | `<mirror_root>/晚会`（目录本身不分地区；单场演出是电影、多段录制是剧集） |
| `演唱会` | 演唱会 | MIXED | `<mirror_root>/演唱会`（目录内分国内/国外；同上） |
| 其它一级分类 | 同名 | 含「电影」→ MOVIE，否则 SERIES | 同名目录 |

用户已确认（2026-10-21，最终版）：

- **库按类型分：电影、电视剧、动画各一个库**，与既有做法一致；
- **动画和动漫合并成一个板块**，只按地区分国内/国外，且**国内/国外只是库内的目录层**；
- 动画库类型 `MIXED`：板块里既有动画电影也有番剧，扫描按文件逐个判定；
- `动漫` 目录名当作动画板块的别名，合并进「动画」库（多个根），不新建库；
- **晚会/演唱会按上次的结论**：晚会不分地区（`晚会/<年代>/…`），演唱会分国内/国外
  （`演唱会/<国内|国外>/<年代>/…`），两者各自一个库；
- **建库后自动全量扫描**。

用户补充确认（2026-10-22）：**所有板块统一走 `<类型>/<国内|国外>/<年代>/<片名 (年份)>/`**，
电影/电视剧/动画/综艺/纪录片/演唱会都分国内/国外；**晚会是唯一不分地区的板块**。
`纪录片` 与 `动画` 一样按文件逐个判定（MIXED）。

用户改判（2026-10-23）：**取消「特摄剧」板块**——特摄不是内容分类，形式决定板块，
剧集形式的特摄进 `电视剧`、电影形式的进 `电影`。镜像里残留的 `特摄剧` 目录不会再建库
（`auto_library` 的 `RETIRED_BOARDS`）。

用户新增（2026-10-23）：**remux 单独成库**——顶层目录 `REMUX` 是一个库（MIXED），
内部沿用 `<类型>/<地区>/<年代>/<片名>`；**分辨率不建层级**（清晰度只在文件名里）。
库在列表里显示为 **影视原盘**（目录名保持 ASCII，归档侧按 `REMUX` 过滤）。
remux 与同片的压制版分属两棵树、互不洗版；同一个目录包里只要有一个视频不带 `REMUX`
标记，整包仍按普通版归档。

## 2. 触发点（三个）

1. **归档 run 结束**：本轮 `organized` 非空 → 立即对账，新建的板块立刻有库并入扫描队列。
2. **启动对账**：进程启动即跑一次，把镜像一级子目录与已注册库比对，补建漏掉的
   （覆盖历史数据、以及进程在两次之间挂掉的情况）。
3. **兜底周期对账**：每 600 秒一次，覆盖「目录从 Lux 之外多出来」（手工整理、别的工具写入）。

## 3. 幂等与安全

- 幂等键 = **库根路径**：已存在的根不再建库；只补该库缺的根（`updated`）。
- 只处理 `mirror_root` 的**一级子目录**；地区、年代层永远不会被当成库。
- 目录下没有任何 strm/nfo 时**不建库**，避免产生空库。
- 建库失败只记 WARN，不打断归档 run。

## 4. 自动扫描策略

建库成功后入队一次**全量扫描**，与手动扫描走同一条任务队列（`ScanJobService` +
`start_library_scan`），不另起并发通道；扫描失败重试沿用现有任务重试逻辑。

## 5. 前置修复（已完成，仅测试库）

`lux-library` 里没有 `动画` 目录，原因是镜像由归档 run 生成，而 115 侧那批 `动画` 是外部工具
整理出来的、从没走过 Lux 归档。2026-10-21 已在**测试库**（`测试库/媒体目录`，未触碰真实库）完成：

1. `动画/<年代>/` → `动画/国内|国外/<年代>/`（141 条：国内 112、国外 29）；
2. 存量年份目录 → 年代目录（电影 5 个、电视剧 8 个年份桶，22 条片；要把年份目录的**内容**
   合并进年代目录，不是把年份目录塞进去）；
3. `动漫/*` 合并回 `动画/*`（动画/动漫合并决定）；
4. `POST /admin/archive/metadata?dry_run=false` 回填镜像；
5. 由自动入库重建「电影 / 电视剧 / 动画」三个库并各扫一次。

真实库（`影视库/媒体目录`）保持原样，等调试完成后再分批复制过来。

## 6. 验收标准

1. 清空库表后跑一次归档 run：非空分类都出现对应库，且扫描已入队。
2. 再跑一次：库数量不变（幂等）。
3. 新增非空分类并重跑：库自动出现，且能在 web「媒体库」看到。
4. 空目录不产生库。
5. 历史数据（已有目录、无库）在进程重启后自动补齐。
6. 国内/国外目录**不会**产生第二个库。

`archive::tests::organizes_titles_into_decades`、`archive::tests::separates_domestic_and_foreign_boards`。
